## Contact semantics (do not collapse)

| Layer | Field | Customer tile? |
|-------|--------|----------------|
| A | `professionalTitle` / activity-specific title | Feeds subtitle when present |
| B | `opportunityRole` (Event Organizer, Group Travel Coordinator, …) | Subtitle **only if A absent** |
| C | `contactRelevance` / `buyerEligibility` | Never tile subtitle |
| D | `buyerEligibleForGate` | Gate / capabilities only |
| E | `displayRole` / `cardContactSubtitle` | **Final card subtitle** |

**Fixture:** Regulatory Information Conference / Lorna Kipfer — `displayRole=RIC Conference Contact`, `opportunityRole=Group Travel Coordinator`. Card must show **RIC Conference Contact**.

## Rules

1. Publication freezes approved presentation fields (including `tileContactPreview.displayRole` and icon bytes).
2. Share/auth attach may normalize but must not re-select research classifications over frozen display values.
3. Browser renderer must display `cardContactSubtitle` / canonical `contact.role` — not independently pick `opportunityRole` when a professional/activity `displayRole` exists.
4. Changing substantive published content requires a new fingerprint and founder approval.
