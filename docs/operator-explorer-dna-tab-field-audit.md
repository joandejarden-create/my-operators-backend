## How data reaches the UI

```text
Airtable (new-base tables) → GET /api/intake/third-party-operators/:id
  → prefill (camelCase) + fields (Airtable column titles) + child rows
  → mergeExplorerPrefill → vm.ex
  → buildPanels(vm) + section modules
```

| Data type | Owner sees | Setup change reflected? |
|-----------|------------|-------------------------|
| **singleSelect / scalar** with binding | KPI value or text | **Yes** when saved to new-base |
| **multiselect** | Lists, chips, filters | **Yes** when writer persists |
| **JSON subsection** (`*_json`, `op_*`) | Tables/cards with defaults until filled | **Yes** when column populated |
| **JSON default only** (no Airtable yet) | Demo/default copy | **No** until Airtable + intake wired |
| **child table** | Leadership, case studies, diligence | **Yes** on child replace |
| **derived** | Counts, compact labels, % | Recalculates from source fields |
| **explorerProfileJson** / skipped | Overview cards | Only if JSON blob updated |
