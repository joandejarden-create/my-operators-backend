# Feature Brief Template

Copy this template when planning a new Dealality feature. See [DEALALITY_PRODUCT_CONSTITUTION.md](./DEALALITY_PRODUCT_CONSTITUTION.md) and [NAMING_AND_COPY_GUIDE.md](./NAMING_AND_COPY_GUIDE.md) before filling it in.

---

# Feature Brief: [Feature Name]

## 1. Objective

What problem does this solve?

## 2. Primary Users

- Owner
- Brand
- Operator
- Advisor
- Capital Partner
- Admin
- Demo User

## 3. User Value

Why does this matter?

## 4. Recurring Value

Why would the user come back?

## 5. Where It Appears

Pages, dashboards, modals, snapshots, print views, or workflows.

## 6. Inputs Required

Deal inputs, company profile data, brand/operator data, market data, source materials, user responses, etc.

## 7. Outputs Generated

What the platform shows or creates.

## 8. AI Behavior

What AI should generate, infer, summarize, classify, or flag.

## 9. Evidence / Interpretation / Next Action

Define which parts are facts, which are interpretations, and which are suggested next actions.

## 10. Data Model

Tables, fields, validation statuses, and usage permissions involved.

## 11. Permissions / Access

Workspace, region, deal, company profile, demo/admin implications.

## 12. UI Requirements

Cards, tables, modals, badges, empty states, confidence labels, print behavior.

## 13. Copy / Tone Requirements

Preferred language and terms to avoid. See [NAMING_AND_COPY_GUIDE.md](./NAMING_AND_COPY_GUIDE.md).

## 14. Edge Cases

Missing data, stale data, conflicting sources, low confidence, unvalidated content, no matches.

## 15. QA Checklist

How to review this feature. See [DEALALITY_QA_CHECKLIST.md](./DEALALITY_QA_CHECKLIST.md) and [../data-intelligence/CONTENT_QA_CHECKLIST.md](../data-intelligence/CONTENT_QA_CHECKLIST.md) if content is involved.

## 16. Definition of Done

Technical, product, data, QA, and documentation completion criteria.
