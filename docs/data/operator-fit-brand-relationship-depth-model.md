# Operator Fit — Brand Relationship Depth Model

**Date:** 2026-08-04  
**Authority:** Evidence-closure founder decisions 1.2–1.3

---

## Separation

| Concept | Meaning | May drive Fit score? | Typical timing |
| ------- | ------- | -------------------- | -------------- |
| **Brand Relationship** | Documented operate/operate-history/announce with brand or parent | Yes (conservative) | Before ranking |
| **Project Approval** | Brand accepts this operator for **this** asset | No inference from portfolio | Usually outreach |

Never equate `Verified Current Relationship` with `Approved for This Project`.

---

## Layer 2 — Brand Company Relationship

Broader current relationship with the parent company (Marriott, Hilton, Hyatt, IHG, Choice, Wyndham, Accor, Sonesta, Radisson, Other).

| Status |
| ------ |
| Strong Documented Relationship |
| Documented Relationship |
| Limited Documented Relationship |
| Historical Relationship |
| Unknown |

Do **not** infer corporate approval.

## Layer 3 — Operator Approval Status (scoped)

Where evidence exists: Approved · Approved With Conditions · Historically Approved · Approval Unknown · Unsupported.

Scope by brand · country · region · hotel type. **No global inference.**

## Layer 4 — Project-Specific Approval

| Status |
| ------ |
| Confirmed |
| Brand Confirmation Required |
| Operator Confirmation Required |
| Both Parties Must Confirm |
| Known Conflict |
| Not Applicable |

Default during Fit: **Brand Confirmation Required** / **Both Parties Must Confirm** — not Confirmed.

---

## Scoring interaction (frozen methodology)

- Portfolio / verified current relationship may contribute compatibility evidence (existing layer).  
- Project Approval remains a **validation item**, not an eligibility hard-fail (unless known hard restriction).  
- Historical relationships must not receive the same confidence as verified current.  
- Substring matches on the word “approval” inside limitations text must **not** count as Approved.
