AI Demand Leak Audit — Admin Workflow

Simple operating checklist for Joan or a future team member. Free audit writes stay isolated from production ADP.

Audit Reports Request Queue Open Sample Report New Request

  1. 1. Create request

    Go to New Audit Request. Capture hotel name, website, market, contact, demand segment, and source.

    Result: status = requested. No production hotel records are updated.

  2. 2. Approve request

    On the request queue, click Approve after a quick qualification check.

    Result: status = approved.

  3. 3. Run audit

    Click Run Audit. Phase 1 creates a leak-audit run with limited territories and stores observations only in the leak-audit store.

    Result: status moves through running → completed.

  4. 4. Review observations

    Open the request detail via API/admin review. Confirm subject mentions, competitor displacement, and demand territories look sensible. Failed provider notes stay on the leak-audit run only.

  5. 5. Generate / open report

    Phase 1 auto-generates the one-page report on run completion. Click View Report and confirm the commercial sections read cleanly for a hotel owner.

    Sales demo: use the sample report.

  6. 6. Mark sent

    After the report is shared with the prospect, click Mark Sent.

    Result: request status = sent; report status = sent.

  7. 7. Promote to pilot

    Only if the prospect agrees to discuss paid monitoring. Click Promote to Paid ADP Pilot, read the confirmation text, then confirm.

    Phase 1.5 result: promotion stub only; status = converted. No production ADP records are created yet.

Safety reminders

  • Never paste full proprietary prompts into the client report.
  • Never write to Census, Brand Explorer, Operator Explorer, or paid ADP monitoring from this workflow.
  • Use cautious language: “evidence suggests,” not “this proves.”
  • Keep the conversation on the limited diagnostic → paid pilot path.
